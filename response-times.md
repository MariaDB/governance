# Response Times

| Event | Timings and deadlines |
|----|----|
| First response to a contribution | 7 calendar days |
| Contribution review | 30 working days, unless a different timeline was communicated explicitly |
| [Maintainer not responding in a joint decision, before escalation](governance.md#31-general-guidelines) | 10 working days. 1 working day if a critical security vulnerability is involved. |
| [Maintainer inactivity before removal](governance.md#22-ceasing-to-be-a-maintainer) | 20 working days |
| [Committer inactivity before removal](committers.md#ceasing-to-be-a-committer-or-a-reviewer) | 1 calendar year |
| [Orphaned subsystem review](governance.md#23-subsystems-without-a-maintainer-orphaned) | 10 working days. Then quarterly to see if a change in the status is needed. |
| [Time before merge for a pull request that needs a simple majority](maintainers.md#voting-and-recording-decisions) | At least 5 working days
| [Time before merge for a pull request that needs a supermajority](maintainers.md#voting-and-recording-decisions) | At least 10 working days

This table summarizes the timing, response expectations, and deadlines defined in the Governance model to ensure project responsiveness and avoid deadlocks. Note that working days exclude vacations and holidays.
